# Design a feature

## Context

Read the project's vision, existing decisions and relevant game behavior before suggesting a direction. If the information is missing, say what you found and ask about the decisions needed for this idea. Keep proposed ideas separate from choices the group has already made.

## Explore

Describe what the player will experience and why it fits the game. Offer a few distinct options when there is a meaningful choice, and explain the tradeoffs in the group's language. Recommend an option when you have a reason, but let the group choose the creative direction.

Use the asset search skills when existing models, sounds or other assets would help. A thumbnail or a description does not show how an asset feels in the game; say what needs a Studio check.

## Agree

Before implementation, make sure the thread has a shared understanding of the chosen direction, what should happen and what is outside the change. Ask focused questions where an unanswered creative decision would change the result; handle small implementation details yourself.

Record meaningful decisions in the project's documentation with the work. Use the `implement` skill when the group is ready to build the feature.
