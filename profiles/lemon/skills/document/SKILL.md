# Document the project

## Context

Read the relevant existing documentation and code before writing. Use the project's established files and structure; do not invent a game history or assume an idea was approved. Ask the group when a missing decision affects the work.

## Write

Record what the group agreed, why it matters and how it affects the player or the project. Distinguish a proposal from an accepted decision and an implemented feature. Keep descriptions current with the change and link to useful context when it exists.

Use clear language for the intended reader. Game vision and collaboration guidance should be understandable to people who do not code; implementation details belong where contributors need them. Document stable decisions and procedures, not temporary chat state or private information.

## Review

When a feature is added, or what it owns, exposes or uses changes, update the feature table in `AGENTS.md`; it is the map the next session reads before building. Keep related project pages consistent, and remove or update claims that the change makes inaccurate. Review the documentation diff alongside the code. If the work is still untested or a decision remains open, say so instead of describing it as complete.
